## Submit through the existing add-on

Open the [existing Developer Hub version page](https://addons.mozilla.org/developers/addon/3062325/versions) using the Mozilla account that owns 0.1.0. Keep the extension ID `tab-leak-guard@local.invalid`. Use the existing add-on's new-version/listing flow to submit to the **listed** channel (“On this site”). If the existing entry is still unlisted, select its option to list on AMO when available; the account's current UI determines that transition. Do not delete the old entry or assign a new extension ID to work around a duplicate-ID error.

Signing an unlisted build and publishing a searchable marketplace listing are separate outcomes. Verify the eventual public listing and version before adding an installation badge to the README. Mozilla documents distribution choices in its [signing overview](https://extensionworkshop.com/documentation/publish/signing-and-distribution-overview/).

## Submission sequence

1. Choose the existing add-on and listed distribution, then upload the production ZIP.
2. Resolve validation errors and inspect warnings.
3. Upload the matching source ZIP and provide the build instructions below.
4. Complete the listing using the proposed copy and links below. Add real screenshots of onboarding, a finding with evidence, and the recovery dialog using synthetic pages.
5. Review the data-use answers against the actual bundle and [privacy statement](privacy.md). The current extension processes data locally and declares no transmitted data; do not confuse this with having no local observations or permissions.
6. Confirm platform/version support based on completed tests. This is a desktop candidate; Android support has not been validated.
7. Submit when the project's remaining release gates are satisfied. Track reviewer messages in the Developer Hub.
8. After approval, download Mozilla's signed XPI, record its checksum, and test installation/update in a disposable profile. Verify the public AMO listing before sharing it as the install URL.

Mozilla's [submission guide](https://extensionworkshop.com/documentation/publish/submitting-an-add-on/) describes package validation, source attachment, listing details, and reviewer notes. Approval timing depends on review; a successful local lint is not an AMO approval.

## Proposed listing copy

**Name:** Tab Leak Guard

**Summary:** Spot sustained tab growth, review the evidence, and recover tabs with local, privacy-first monitoring.

**Description:**

Tab Leak Guard helps you investigate tabs that keep growing while you browse. It observes sustained live-page growth and explains the evidence behind each finding.

- Start a temporary 15-minute session, monitor selected sites, or authorize all regular websites.
- Review evidence quality, freshness, and the reasons a tab looks concerning.
- Receive optional notifications with generic text by default.
- Snooze findings, ignore sites, or stop monitoring whenever you choose.
- Review an exact unload or reload action before confirming it.

Analysis and history stay in Firefox. There are no accounts, analytics, or automatic data uploads. The extension does not read page text or form values.

Detection is heuristic. Firefox does not expose exact per-tab memory through this extension's APIs, and some leak types are not observable. Allow about five minutes for learning. Version 0.1.1 requires confirmation for every recovery action; automatic recovery is unavailable.

**Suggested category:** Tabs, if offered by the current AMO form.

## Reviewer notes

The extension is built from TypeScript with locked esbuild tooling. Extract the source archive, use Node.js 24.2.0 and npm 11.4.2, and run `npm ci` then `npm run build:production`. The `dist/` directory is the production extension. Full instructions are in AMO_SOURCE_SUBMISSION.md. There are no runtime package dependencies, application network services, telemetry, or remote code.

Automatic recovery is compile-time disabled. All recovery in 0.1.1 requires explicit two-phase consent. Optional host permissions enable selected-site/all-site collection; manual sessions use activeTab. `webNavigation` binds observations and consent to the current document. The initial learning interval is approximately five minutes. `npm run fixtures` serves deterministic test pages at localhost:4173 for review; no login or paid service is required.
