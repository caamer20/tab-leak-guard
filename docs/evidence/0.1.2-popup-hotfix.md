# 0.1.2 popup hotfix validation

Date: 2026-09-18 (America/Los_Angeles). Host: macOS. Node 24.2.0, npm 11.4.2, Firefox Release 155.0.1.

## Reproduction and fix

The user reported that clicking the publicly listed 0.1.1 extension showed only a vertical scrollbar. Mozilla's developer dashboard confirmed 0.1.1 was approved and listed.

`npm run build && npm run smoke:headless`, with the new popup check against the unchanged 0.1.1 CSS, reproduced the failure in a disposable Firefox profile: the toolbar popup browser measured **16 × 600 CSS pixels**. The check failed as intended.

Changing the body from `width: min(430px, 100vw)` to `width: 430px; max-width: 100%` removes the circular dependency between Firefox's preferred-content width and the viewport it is calculating. No detection, permission, persistence, or recovery logic changed.

The same Firefox test against 0.1.2 passed, measuring **430 × 600 CSS pixels**. Content inspection confirmed:

- Heading: `Resource monitor`.
- Monitoring status: `On-demand monitoring` (not the initial loading state).
- Content viewport and body width: 430 pixels.
- Settings button had positive width and was fully inside the viewport.
- Temporary installation, fixture tab loading, add-on reload, and cleanup passed.

Command: `npm run smoke:headless`. Executable: `/Applications/Firefox.app/Contents/MacOS/firefox`. Test fixture: local server on an ephemeral localhost port. No changes were made to the user's regular Firefox profile. One initial launch failed while Firefox was applying a browser update; a subsequent launch reproduced the defect and two fixed-build runs passed.
